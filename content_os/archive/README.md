# Fit Biblia Product Archive

## Human trigger
Canonical explicit command:

`ELFOGADOM A TERMÉKET`

Narrow aliases: `TERMÉK ELFOGADVA`, `MEHET AZ ARCHÍVUMBA`, `EZ A VERZIÓ ELFOGADVA`.

Ordinary approval such as `jó`, `tetszik`, or `mehet tovább` is not an archive trigger.

## Lifecycle
`DELIVERED → HUMAN_ACCEPTED → PACKAGE_FREEZE → INDEX → COMPRESS → HASH → DRIVE_ARCHIVE → PRODUCT_ARCHIVE LEDGER WRITE → ACCEPTED_ARCHIVED`

Acceptance never means publication. Preserve the current `publication_status` exactly.

## Canonical naming
`YYYY-MM-DD__Human-readable-title__Platform-OutputType__vX.Y`

ZIP:
`YYYY-MM-DD__Human-readable-title__Platform-OutputType__vX.Y__PACKAGE.zip`

## Required package groups
- `01_PRODUCT`
- `02_COPY`
- `03_CONTENT_MASTER`
- `04_RESEARCH`
- `05_MANIFESTS`
- `06_REPRODUCE`
- `07_ACCEPTANCE` is generated by the packager
- `00_INDEX.md` is generated by the packager

The packager rejects incomplete groups, missing human acceptance, duplicate files, and overwrite attempts.

## Drive target
Root folder ID: `1E1OSUxIZ-RFlzwwJuoSZ_n-zCh8s6M3Q`

Hierarchy:
`PRODUCT_ARCHIVE/YYYY/YYYY-MM/<archive_name>/`

Upload the ZIP only after local package validation succeeds. Then append the permanent Drive refs and hashes to `FIT_BIBLIA_CONTENT_LEDGER / PRODUCT_ARCHIVE`.

## Executable
`content_os/archive/product_archive.py`

Example:

```bash
python -m content_os.archive.product_archive archive_spec.json ./archive_staging
```

The result provides `package_sha256` and `content_tree_sha256`. Store both in the Ledger after Drive upload.

## Immutability
An accepted archive is never overwritten. Any content change after acceptance creates a new semantic version.
